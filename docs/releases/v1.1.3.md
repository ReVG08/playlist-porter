# Playlist Porter v1.1.3 — Account connection fix

Fixes the desktop sign-in problem reported when connecting TIDAL (and the same path for Spotify).

## Fixed

- Connect opens your normal system browser, rather than loading sign-in inside Playlist Porter. The desktop app remains open to receive the local OAuth callback and refresh its connection status.
- Provider redirects and new windows cannot leave the app stuck on an embedded sign-in page.
- TIDAL requests use the documented JSON:API media type, avoiding obsolete content negotiation after sign-in.
- Desktop callback URLs always match the local server at `http://127.0.0.1:8787`. Public Client IDs are saved in Settings and are no longer overridden by an unrelated launch-directory `.env` file.
- Clear dialogs explain browser-launch failures and an occupied local port instead of silently quitting.
- Added regression coverage for desktop navigation, PKCE callbacks, token refresh, local settings, and TIDAL requests.

## Install or update

Validation: 78 automated tests pass, along with lint, TypeScript checks, and desktop packaging. The packaged macOS app was smoke-tested to confirm both Connect buttons leave the local desktop UI open. Provider token exchanges are covered with mocked responses; a real-account transfer was not performed for this release.

Quit the old app before installing. Existing saved Client IDs and locally encrypted tokens are retained.

- **Apple Silicon Mac:** download `Playlist-Porter-1.1.3-mac-arm64.dmg`.
- **Intel Mac:** download `Playlist-Porter-1.1.3-mac-x64.dmg`.
- **Windows:** download `Playlist-Porter-1.1.3-Windows-x64-Setup.exe`, or use `Playlist-Porter-1.1.3-Windows-x64-Portable.exe` without an installer.

On macOS, open the DMG and drag Playlist Porter into Applications. ZIP builds are also included. `SHA256SUMS.txt` contains download checksums.

## Connect your accounts

1. Open Settings and save your public Spotify and TIDAL developer-app Client IDs. No client secret is required.
2. Register these exact redirect URLs in the corresponding developer dashboards:
   - Spotify: `http://127.0.0.1:8787/auth/spotify/callback`
   - TIDAL: `http://127.0.0.1:8787/auth/tidal/callback`
3. Select Connect. Complete authorization in your browser while keeping Playlist Porter open.
4. Once the browser says Connected, return to Playlist Porter. If necessary, Disconnect and reconnect the affected service.

Provider app-access rules, scopes, user allowlists, and account eligibility still apply; this update does not bypass them. Automated tests use mocked provider responses, not real user credentials. See the [README tutorial](https://github.com/ReVG08/playlist-porter#step-by-step-tutorial) for details.

Community builds are unsigned and may trigger operating-system reputation warnings. Playlist Porter remains local-first: no hosted token service, telemetry, audio downloading, or proxying.
